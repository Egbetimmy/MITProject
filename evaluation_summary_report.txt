4. LATENCY TIMEOUT-CENSORED DATA VERIFICATION
---
* Verification: Raw k6 JSON parses confirm that P99 values at or near 60,000ms
  are client-side timeout-censored metrics, not actual response times.
* Evidence: In RUN_T4_1_k6.json:
  - Aggregate P99 Latency: 60,275.10 ms (representing 100% aborted checkouts).
  - Successful Request P99 Latency: 4,577.68 ms.
  - Successful Request Average Latency: 2,437.13 ms.
* Conclusion: Under saturation, the tail latency is bounded by the client-side
  60s timeout ceiling, indicating infinite queue growth and service dropouts.

6. TRIAL-LEVEL STATISTIONAL SIGNIFICANCE (N=10)
---
To prevent pseudoreplication, tests were performed treating each trial run as a
single data point. All success rate distributions failed Shapiro-Wilk normality
tests (p < 0.05), requiring the non-parametric Mann-Whitney U test.

* Both vs. Prediction-Only (Gating Ablation):
  - Welch's t-test: t = 3.3048, p = 0.0091 (Significant)
  - Mann-Whitney U: U = 82.5, p = 0.0061 (Highly Significant, p < 0.01)
  - Conclusion: Edge route-gating is required to protect downstream services from
    total transaction collapse.

* Both vs. Shedding-Only (Forecasting Ablation):
  - Welch's t-test: t = -0.4564, p = 0.6536 (Not Significant)
  - Mann-Whitney U: U = 45.5, p = 0.7564 (Not Significant, p > 0.05)
  - Conclusion: Across a full 120s run, proactive forecasting does not yield a
    statistically significant macro-level success rate benefit over reactive shedding.
    Forecasting's utility is localized to reducing transient dropouts at spike onset.

---
7. IN-PROCESS CO-STARVATION FINDING
---
* Finding: Disabling gating in Prediction-Only mode leads to a thread starvation loop.
* Mechanism: Without gating, all GET/POST requests flow downstream, saturating DB
  connection pools. This causes 16,347 TaskCanceledExceptions inside the gateway.
  Handling these exceptions starves the shared .NET thread pool.
* Impact: Because the forecasting engine runs in-process as an IHostedService background
  worker, it gets starved of execution slots. Logs reveal that the forecasting loop ran
  16 times in the first 24s and then halted entirely for the remainder of the run.
* Recommendation: Out-of-process forecasting execution or mandatory edge gating is
  necessary to prevent predictive self-defense systems from starving themselves.
